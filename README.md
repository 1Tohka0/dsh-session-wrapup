# 对话收尾 · dsh-session-wrapup

给 DeepSeek Harness（DSH）加一颗「🧹 收尾」按钮：**把这次对话在工作区里产生的文件和文件夹全摆出来，分好类、标好重要性，勾一下收进回收站；会话本身也能一起收尾。**

对话里让 AI 做一份 PPT，交付了 pptx，但工作区里还躺着抽页脚本、临时 txt、渲染出来的 png、中间 md、`__pycache__`。你要的从来不是「等 30 天自动清」，而是**东西交了，剩下的当场清掉，我看得见每一条是什么**。

---

## 它做三件事

1. **列清单** —— 从会话日志里还原「这次对话碰过/新建的文件和文件夹」，分六组，每条都写清为什么这么判。
2. **删东西** —— 勾选后收进 `$DSH_HOME/_trash/<时间戳>/wrapup/`，3 天后才物理消失。文件夹整包搬走，删完顺手收掉本次新建的空目录。
3. **收尾会话** —— 把这个会话记进账本；它闲置满 30 分钟后，**下次启动 DSH** 时会话日志被收进回收站，`workspace.json` 同步摘掉。

清单里**没有**的东西：DSH 自己的数据（会话、附件、插件、运行时），以及插件自己的源码。

---

## 六组，一眼决定

| 分组 | 含义 | 默认 |
| --- | --- | --- |
| 交付物 | 你展示过、在交付目录里、或是成品后缀 | **保留**（不能勾） |
| 文件夹 | 会话期间新建的文件夹；删除时整包搬走 | 勾选（含交付物时不能勾） |
| 其他 | 认不出来的 | 勾选 |
| 中间产物 | `.md` `.txt` `.json` 这类过程草稿 | 勾选 |
| 中间脚本 | `.py` `.js` `.ps1` 这类临时脚本 | 勾选 |
| 临时文件 | 临时目录 / `.tmp` `.log` 这些 | 勾选 |

**选择方式**（这次更新的重点）：

- 每行一个勾选框，点一下选中/取消。
- 每组标题左边有一个**三态总勾**：全选 → 部分选（横杠）→ 全不选。
- 勾文件夹会**自动带上里面的全部文件**；反过来，里面的文件全勾上时，文件夹也会自动变勾。
- 底部有 **恢复默认勾选** / **全选** / **全部取消** 三个总开关。
- 顶部实时显示「勾了几项、一共多大」；文件夹只按最外层算一次，不会重复计体积。

## 安装

DSH 的插件是「bundle」：一个带 `cordis.patch.yml` 的 npm 包。把仓库克隆到任意目录：

```bash
git clone https://github.com/1Tohka0/dsh-session-wrapup.git
```

然后让 DSH 装上它：

```
plugin_manager install_bundle   target = <本仓库的绝对路径>
```

装完在插件列表里能看到 **对话收尾**（entryId 形如 `include:dsh-session-wrapup`），图标是一把蓝扫帚。

也可以手动写进 `$DSH_HOME/profiles/<profile>/package.json` 的依赖：

```json
"dsh-session-wrapup": "link:D:/path/to/dsh-session-wrapup"
```

然后重启 DSH。**只依赖 Node 20+，没有第三方依赖，不需要构建。**

## 用

1. 会话标题右边点 **🧹 收尾**。
2. 弹窗按六组列出这次对话碰过的东西。扫描上限是 12 层、2000 个文件；真的超了，面板顶部会有一条「可能还有没列出来的」提示，不会假装扫全了。
3. 勾选要删的；文件夹可以整包勾。
4. 底部：
   - **只删勾选的** —— 只删文件和文件夹，会话留着。
   - **删掉并收尾会话** —— 删东西 + 记账，`30 分钟`后生效。
   - 记账之后再打开面板会多一个 **取消收尾**，随时反悔。
5. 这一轮还在输出时，按钮是灰的（「等这一轮说完…」），每 2.5 秒自己复查。

## 清单是怎么来的

不是猜的。会话日志 `$DSH_HOME/sessions/<工作区>/<会话>/session.v4.jsonl.zstd` 是**多帧串接的 zstd**，本插件按 magic 逐帧解，然后：

1. `deliverables/presented` 事件 → 你点开过的东西，最可信；
2. `tool/call` 参数里的路径，包括**相对路径**（按会话工作目录解析），只看会写文件的工具（`write` `edit` `present` `office_*` `generate_image*` …）；
3. 兜底：工作目录里「会话开始之后被改过/新建」的文件**和文件夹**。判断同时看 `mtime`、`ctime`、`birthtime`——解压或复制保留了旧修改时间的文件也能抓到。默认深度 12、最多 2000 个，跳过 `node_modules` `.git` 这类依赖目录和点开头的隐藏目录，并在清单里说明跳过了多少。
4. 新建文件夹里的内容整体算「这次产生的」，不再被单个文件的旧时间骗过去。

**已经不在磁盘上的路径不会出现在清单里** —— 所以删完再打开不会看到幽灵条目。

## 分层：小白也能看懂的地图

整个插件只有五层，**一层只做一件事**。想改什么，先在这张表里找到对应的一层，别到处翻。

```
┌──────────────────────────────────────────────┐
│ ① 界面层  client.js                           │
│   标题栏按钮、弹窗、分组、勾选、删除结果文案      │
│   你看到的都在这里；改颜色/文案/按钮先看它        │
├──────────────────────────────────────────────┤
│ ② 接口层  index.js                            │
│   六条 HTTP 路由、参数校验、同源检查             │
│   浏览器只跟它说话；它自己不碰磁盘               │
├──────────────────────────────────────────────┤
│ ③ 大脑层  lib/                                │
│   artifacts 读日志 → scan 组装清单 →            │
│   classify 分类 → trash 真的挪文件 →           │
│   queue/sessions 记账与清理                     │
│   所有规则和危险操作都在这里                     │
├──────────────────────────────────────────────┤
│ ④ 命令行  bin/wrapup.mjs                      │
│   和界面共用 ③，不开 DSH 也能扫/删/记账          │
├──────────────────────────────────────────────┤
│ ⑤ 规则层  rules.json + 你的覆盖文件             │
│   哪些后缀算交付物、哪些算临时、扫多深            │
└──────────────────────────────────────────────┘
```

一句话记法：**① 负责好看，② 负责传话，③ 负责干活，④ 是备用遥控器，⑤ 是配置文件。**

文件地图：

```
index.js          Host 半边：六条路由 + 校验，所有活都交给 lib/
client.js         浏览器半边：标题栏按钮与弹窗，免构建
lib/config.mjs    所有路径与阈值（想改「多久算还在写」看这里）
lib/artifacts.mjs 会话日志 → 文件/文件夹集合（只读）
lib/classify.mjs  分类规则与加载/覆盖
lib/scan.mjs      组装清单（纯计算，无缓存）
lib/trash.mjs     两阶段删除，唯一会 rename 文件的地方
lib/queue.mjs     收尾账本 wrapper
lib/sessions.mjs  判活、删会话、同步 workspace.json、启动清理
bin/wrapup.mjs    命令行入口
rules.json        默认分类规则
test/             核心行为的回归测试
```

**设计约束：①、②、④ 都只调用 ③，不各写一份逻辑。** 所以「为什么命令行和面板结果一样」不是巧合，是结构保证的。

## 安全：四道闸

1. **同源** —— 只接受 `Origin` 与自身相同的 POST，别的网页不能遥控你删文件。
2. **只在工作区** —— `$DSH_HOME` 下面的一切在扫描时被排除，删除时再拒一次。
3. **危险路径拒绝** —— 工作区本身、它的上级、盘符根、`$DSH_HOME` 及其上级，整包删除一律拒绝；父子一起选中时只挪最外层，不会重复删。
4. **活着的会话不动** —— 面板 10 秒内写过就拒绝记账；启动清理要求**闲置满 30 分钟**才动手。

另外：删除永远是「先 rename 进 `_trash`」，误点能捞。

文件夹还有一条软闸：**里面有交付物时，扫描阶段就把它标成「保留」**，面板里勾不动；就算绕过界面直接调接口，Host 也会再拒一次。

## 改分类规则

默认规则在仓库的 `rules.json`（有中文注释）。**不要改仓库里的那份**，改你自己的：

`$DSH_HOME/state/wrapup-rules.json`，只写要覆盖的项，例如「`.ps1` 我要留」：

```json
{
  "scriptExt": [".py", ".js", ".mjs", ".ts", ".sh"]
}
```

保存后再点一次收尾就生效（每次扫描都会重读规则）。

## 命令行

同一个 `lib/`，所以命令行和界面行为完全一致：

```bash
node bin/wrapup.mjs scan                 # 打印清单（加 --json 给程序用）
node bin/wrapup.mjs delete --paths "a;b" # 按路径删（会先重扫一遍）
node bin/wrapup.mjs delete --all-deletable --dry   # 预览「建议删」的全部
node bin/wrapup.mjs mark --keep "a;b"    # 记账
node bin/wrapup.mjs unmark               # 撤销
node bin/wrapup.mjs status               # 账本里有什么
node bin/wrapup.mjs finish --dry         # 看看启动清理会删哪些会话
```

环境变量：`DSH_HOME`（必需）、`DSH_SESSION_ID`（默认会话）。
退出码：`2` 参数错、`3` 会话还在写 / 路径已失效 / 选中的是要保留的交付物。

## 开放吗？好改吗？好回退吗？

**开放。** 仓库是公开的，MIT 协议：可以读、改、fork、自己发一版，保留版权声明即可。

**好改。** 零第三方依赖、不需要构建，改完刷新页面/重载插件就生效。按上面的分层找入口：

| 想做的事 | 改哪里 |
| --- | --- |
| 改文案、颜色、按钮、分组顺序 | `client.js` |
| 加一个接口/改请求参数 | `index.js` |
| 改「什么算交付物」 | `rules.json` 或你的 `wrapup-rules.json` |
| 改扫描范围、漏检 | `lib/artifacts.mjs` + `lib/scan.mjs` |
| 改删除行为/回收站 | `lib/trash.mjs` |
| 改「多久算闲置」 | `lib/config.mjs` |

**好回退。** 每次发布都打 tag，没有构建产物要清理：

```bash
git tag                     # 看有哪些版本
git checkout v1.0.3         # 退到旧版
# 或者回到主线
git checkout master
```

退完：

- 改的是 `client.js` → **刷新页面**；
- 改的是 `index.js` / `lib/` → 在插件列表里关一次再开，或重启 DSH。

升级同理：`git checkout v1.1.0`（或 `git pull` 到最新）。link 安装不会复制文件，切换 tag 就是切换运行中的代码。

## 常见问题

**按钮没出现** —— 页面刷新一次（client bundle 要重新拉）。旧版本插件没卸载就装新的，会出现两个按钮。

**点「删掉并收尾会话」，会话没马上消失** —— 设计如此：闲置满 30 分钟 + 下次启动 DSH 才删。想立刻看效果跑 `node bin/wrapup.mjs finish --dry`。

**清单里有文件但我明明删了** —— 重新打开面板即可（每次都是实时扫描）。

**文件夹怎么删不掉** —— 看它是不是被标成了「保留」：里面有交付物时整包不能删，但可以把里面不要的文件单独勾掉，剩下的交付物留着。

**工作区特别大，打开面板要等** —— 关掉兜底扫描：`{"sweep": {"enabled": false}}` 写进 `wrapup-rules.json`；或者把 `maxDepth` / `maxFiles` 调小。
